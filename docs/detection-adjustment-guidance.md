# 수동 C2 탐지 조정 가이드

## 목적

최초 분석 후보에 포함되지 않았지만 분석가가 Flow를 수동으로 C2라고 확정한 경우, 동일 데이터셋을 다시 평가하여 다음 질문에 답한다.

1. 어떤 탐지 조건이 실제로 성립했는가?
2. 각 조건의 점수 기여와 감점은 무엇인가?
3. 후보 임계점까지 몇 점이 부족했는가?
4. 탐지기 가중치 또는 후보 임계점을 최소한으로 어떻게 조정할 수 있는가?
5. 추천 설정을 적용한 재분석 결과는 무엇인가?

## 사용 시나리오

### 기본 시나리오: 점수 부족으로 누락된 C2

1. 분석가는 후보 상세 또는 분석 Flow 탐색에서 의심 Flow의 Payload와 메타데이터를 검토한다.
2. 외부 조사나 리버스 엔지니어링 결과를 근거로 `C2`를 선택하고 분석가 메모를 남긴다.
3. Controller가 수동 판정을 저장한 뒤 같은 분석 데이터와 당시 allowlist를 사용해 전체 탐지기를 다시 실행한다.
4. View는 해당 외부 IP에 생성된 탐지 근거, 원점수, 현재 가중치, 감점, 최종 점수와 후보 기준을 표시한다.
5. 시스템은 1.25~2.0 범위에서 탐지기 하나의 가중치만 바꿔 후보 기준을 넘기는 최소 변경안을 탐색한다.
6. 가중치만으로 넘을 수 없으면 현재 점수에 맞춘 후보 기준 완화안을 보조안으로 제시한다.
7. 분석가는 오탐 위험 안내를 검토하고 `추천 설정으로 재분석`을 선택한다.
8. 새 분석 작업에서 해당 IP의 후보 생성 여부와 변경 전후 점수를 확인한다.

### 예외 시나리오

- 최신 수동 판정이 C2가 아니면 가이드를 생성하지 않는다.
- 현재 조건에서 탐지 근거가 전혀 없으면 가중치 변경으로 해결할 수 없음을 명시하고 Payload 서명 또는 탐지 조건 확장을 안내한다.
- 분석 당시 allowlist 때문에 제외된 IP라면 점수 조정보다 정책 검토를 먼저 권고한다.
- 이미 후보 기준을 넘긴 IP라면 설정 변경 없이 당시 후보·정책 상태를 확인하도록 안내한다.

## 스토리보드

### 화면 1: Flow 수동 판정

- 위치: 후보 상세의 `관련 Flow` 또는 분석 상세의 `모든 Flow 탐색`
- 입력: C2 판정, 신뢰도, 분석가 메모, 선택적 Payload 서명 생성
- 동작: C2 저장 직후 탐지 조정 가이드를 자동 계산

### 화면 2: 탐지 조정 가이드

- 상태 요약: `최초 분석 미탐`, 현재 점수, 후보 기준, 부족 점수
- 성립 조건: 탐지 표시명, 탐지기, 기본 기여도, 현재 가중치 반영 기여도, 조건 설명과 지표
- 점수 조정: 단일 호스트·표본 부족·고용량 등 감점 항목
- 제한 안내: 동일 데이터셋에서의 점수 반사실 계산이며 별도 데이터의 오탐률 예측은 아님

### 화면 3: 추천 비교 및 적용

- 각 추천: 변경 항목, 현재값→추천값, 예상 점수, 점수 증가량, 위험도와 위험 설명
- 기본 선택: 가장 작은 단일 탐지기 가중치 변경
- 보조 선택: 후보 기준 완화 또는 allowlist 정책 검토
- 동작: `추천 설정으로 재분석`

### 화면 4: 재분석 결과

- 새 분석 작업 상세로 이동
- 기존 분석은 변경하지 않음
- 새 작업의 detector weights와 minimum candidate score에서 대상 IP가 후보가 됐는지 확인

## 추천 계산 규칙

- 원본 분석 작업과 원본 allowlist snapshot을 사용한다.
- 탐지 및 scoring 구현을 View에서 복제하지 않고 Analysis 엔진을 실제 재실행한다.
- 가중치 후보는 `1.25, 1.5, 1.75, 2.0`이며 기존값보다 큰 값만 평가한다.
- 후보 기준을 넘기는 단일 탐지기 변경안만 추천한다.
- 여러 변경안이 있으면 변경 폭, 예상 점수, 탐지기 이름 순으로 정렬한다.
- 가중치 상한은 scoring 엔진과 동일하게 2.0이다.
- 후보 기준 완화는 가중치로 해결할 수 없고 현재 점수가 0보다 클 때만 제안한다.
- 추천값은 자동으로 전역 기본값이나 프리셋에 저장하지 않는다.

## API 계약

`GET /api/v1/analysis-jobs/{job_id}/flows/{flow_id}/detection-guidance`

전제:

- 분석 작업과 Flow가 존재한다.
- 해당 Flow의 최신 수동 판정이 `C2`다.

주요 응답:

- `conditions`: 실제 생성된 탐지 근거와 점수 기여
- `adjustments`: 실제 적용된 점수 조정
- `current_score`, `minimum_candidate_score`, `score_gap`
- `recommendations`: 변경 전후 값, 예상 점수, 위험도, 재분석 payload
- `recommended_reanalysis`: View의 원클릭 재분석 기본 payload
- `warnings`: 계산 범위와 오탐 위험 안내

## 안전 원칙

- 수동 C2 판정은 탐지 결과를 덮어쓰지 않고 별도 감사 기록으로 유지한다.
- 추천은 기존 분석을 수정하지 않고 새 재분석 작업을 생성한다.
- 낮은 임계값 또는 높은 가중치가 정상 트래픽 점수도 올릴 수 있음을 항상 표시한다.
- 별도 검증 데이터셋 없이 오탐률이나 탐지율 수치를 추정하지 않는다.
