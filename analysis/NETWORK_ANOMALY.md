# Network anomaly POC contract

The first section describes the retained legacy API. The production pattern report uses `c2hunter_analysis.network_report.analyze_network_report`; its separate bounded-epoch policy is documented below.

Legacy entry point: `from c2hunter_analysis.network_anomaly import analyze_network_anomalies`.
Call `analyze_network_anomalies(records, *, max_packets=100000, max_flows=1000)` with `parse_pcap(..., retain_network_evidence=True, retain_packet_bytes=False).records` **before flow aggregation**. Evidence retention defaults to false, preserving existing `Flow(**record)` callers. No C2 scoring/model/schema replacement. Records lacking packet evidence are accepted as incomplete; no guesses from aggregate flags.

Returns a plain JSON-safe dict with `version: "network-anomaly-v1"`, `summary`, `flows`, `warnings`, and `limitations`. Each flow has `sensor_id`, `interface_id`, `protocol`, `endpoint_a`/`endpoint_b` (`ip`, `port`), `observed_directions` (`a_to_b`/`b_to_a`, each packets/bytes), `metrics`, `warnings`. Metrics: `syn_retransmissions`, `data_retransmissions`, `duplicate_acks`, `matched_resets`, `udp_duplicate_candidates`, `icmp_errors`, `icmp_error_details`, `observed_rtt_ms` (count/min/max/mean), `interarrival_variation_ms` (directional count/min/max/mean/stddev), `ttl_observed` (directional min/max). Counters count observed repeats, not proven network loss. Missing measurement summaries have count 0 and null extrema/mean.

`metrics.icmp_error_details` is an array of at most 16 objects:

```json
{"type":3,"code":1,"reporter_ip":"203.0.113.1","quoted_flow":{"source_ip":"10.0.0.1","destination_ip":"203.0.113.1","source_port":50000,"destination_port":443,"protocol":"UDP"}}
```

`quoted_flow` is null when unavailable. Errors appear on the ICMP flow and, when the quoted TCP/UDP tuple exists in the same sensor/interface, on that transport flow. Do not sum these counters as unique capture-wide errors. Quoted association does not add reverse-direction transport packets.

Endpoint ordering is deterministic, not an inferred client/server. Missing or null `capture_interface_id` is retained as the explicit unknown group (`interface_id: null`), separate from every known interface including 0. Unknown records with the same sensor/protocol/endpoints share that group; it does not establish a shared capture vantage. Historical/aggregate records retain directional packet/byte totals and carry `INCOMPLETE_PACKET_EVIDENCE`; packet measurements cannot be inferred from aggregate flags. Scope is per sensor AND capture interface: never correlate unsynchronized vantages. A missing direction (`ONE_DIRECTION_OBSERVED`) is unknown capture visibility, NOT evidence of bad routing. No route bypass or asymmetric-route verdict is emitted. TTL and ICMP are supporting observations only, not proof of path identity. Interarrival variation is NOT one-way jitter. Duplicate ACK needs repeated seq/ACK/nonzero window, no payload or SYN/FIN/RST/URG, and outstanding reverse-direction data. TCP sequence, ACK, window, payload length and complete packet evidence are required. RTT excludes retransmitted/ambiguous ranges (Karn), including SYN retries, and measures capture-point request/response time (including delayed ACK), not host end-to-end latency. UDP duplicates are directional payload-hash/length candidates, never transport retransmission. All counts remain lower bounds under capture gaps/limits; duplicate capture itself may mimic retransmissions.

Parser additions are opt-in packet-record evidence only. Existing aggregate Flow and PacketObservation are deliberately unchanged. Default scan limit is 100000 records (caller may choose 1..2000000), output limit 1000 flows (caller may lower), and correlation identities are capped at 256 per flow. `PACKET_LIMIT_REACHED`/`FLOW_LIMIT_REACHED` set summary truncation; `FLOW_STATE_LIMIT_REACHED` disables further correlation for that flow. ICMP detail output is capped at 16 per flow. A gap over 60 seconds clears correlation state; a new TCP SYN or RST resets the connection epoch. FIN closes one sending direction; TCP state is retired after both directions' FINs have been acknowledged, preserving outstanding evidence during half-close. Non-monotonic timestamps disable subsequent correlations for that flow. Truncation/incomplete warnings and limitations must be shown by consumers. This is bounded capture-local observation, not a loss/latency diagnosis.

TCP ACK correlation uses bounded extended sequence coordinates across the 32-bit wrap boundary. Stale, beyond-observed-frontier or half-space-ambiguous ACKs cannot retire data or establish duplicate-ACK evidence. Existing conservative RTT ambiguity exclusions remain; this is not a full TCP reassembly stack.

For SLL2 packet evidence, the parser preserves observation-point isolation using a capture-local opaque uint32 identifier for each `(global container interface ordinal, SLL2 ifindex)` pair. This identifier is not the original OS interface index. Mapping is deterministic in capture order, collision-free with container interface ordinals, and capped at 65,536 entries. An unknown zero ifindex or exhausted mapping yields incomplete packet evidence rather than cross-interface correlation. Non-SLL2 IDs and raw export container-interface IDs, packet ordinals and bytes are unchanged. Separate captures still require distinct caller-owned source namespaces.

## Production pattern report: bounded epoch recovery (ND-03)

This section applies only to `analyze_network_report` (`network-pattern-report-v1`), not the legacy 256-state API above. Wire schemas, source namespaces and TCP serial/half-close helpers are unchanged. Production limits remain 8,192 tracked flows, 4,096 retained correlation identities per flow and 131,072 globally. Credits count exactly UDP identities plus both TCP directions' `seen` identities, not SYN/closure markers. A failed reservation consumes no credit; clearing returns each retained identity once. Recovery does not evict another flow or bypass a full global budget.

A correlation-limited flow retains a fixed pair of trusted directional SYN sequence anchors and a last-observed timestamp watermark. These are independent of the SYN response map and allocating correlation stores: cap/incomplete clearing and a matching SYN+ACK pop must not erase the anchor. Limited records receive only bounded identity/time/completeness and epoch checks, without history sets, LRU eviction or scans of other flows.

Analysis resumes only on a complete valid record satisfying either:

- A TCP SYN with none of ACK/RST/FIN/URG set, whose sequence differs from a **known current-epoch anchor in the same direction**; or
- Strictly more than 60 seconds since the last valid identity/time observation in this flow's sensor/interface/protocol/endpoint scope.

A same-SYN repeat, control flag or unknown pre-limit SYN is not new-epoch proof. A midstream-limited flow cannot learn an arbitrary suppressed SYN and use it to justify later recovery; it waits for independent idle. Complete controls can independently satisfy idle. Incomplete records never themselves recover, even after a long gap. All identity/time-valid records, including incomplete and suppressed controls/data, advance the observation watermark before the next record, so sustained omitted traffic cannot manufacture idle from the last *evaluated* packet. The idle comparison precedes the current watermark update. Timestamp regressions permanently disable correlation as before; no new clock authority or exact-tick representation is introduced.

Epoch marker ownership is explicit: ordinary new SYN replaces the epoch anchor, RST and fully acknowledged bidirectional FIN retire it, and idle/recovery reset it before processing the new epoch. A half-close does not retire it. Cap and incomplete correlation clears preserve the anchor; historical SYN replay detection across multiple epochs is not promised. RTT correlation state cannot span the cleared epoch. Tracking/incomplete gaps and idle break measurement adjacency rather than manufacturing cross-gap RTT or spacing.

Recovery never resets prior observations, `incomplete_records`, `tracking_limited_records`, `CORRELATION_LIMIT_REACHED`, lower-bound/truncated status, or measurement-gap qualification. A genuine post-recovery repeat can therefore produce `anomaly_observed` while coverage remains incomplete. Parser/source qualifiers also survive worker publication, saved/public API projection, deterministic AI input projection and Web presentation. This does not add packet evidence to native sensor aggregates and does not establish LIVE capture or model interpretation capability.

Permanent regression witnesses are the analysis/controller epoch tests and `web/tests/network_epoch_fixture.py` / `NetworkEpochRecovery.test.tsx`. The portable helper creates bounded checksum-valid PCAPs, exercises the real parser, `FlowRecord`, worker, SQLite result consumption/reopen and public ASGI GET, and projects AI input without invoking a model. It includes actual unsupported-EtherType parser omission, same-epoch suppression and bidirectional normal controls. Report/input bytes are deterministic; public job UUIDs/lifecycle times are intentionally not. The ASGI transport and Web fetch bridge are test-local, not deployed-browser or real NIC acceptance.

## Production pattern report: observed family retention (ND-04)

New analyses retain one representative of each **observed** pattern family before filling the remaining output slots. Every choice uses the unchanged total order `(-group.event_count, repr(group_key))`, where `group_key = (sensor, interface, protocol, pattern, peer)`. Representatives are the first group of each family in that order. If there are fewer slots than families, only the highest-ranked representatives fit. Remaining slots use the original order excluding already chosen groups; the final selected set is sorted by that same order. This is frequency order, not a severity/risk ranking. No unobserved family is invented.

Defaults remain 20 groups / 3 examples; maxima remain 100 / 10. For 20 UDP groups with three events each plus one matched-reset group, default selection is 19 UDP groups and the reset, with 21 observed groups and one omitted group. Selection does not change observations, event/affected counts, sensor/interface/peer separation, source/parser warnings, ND-03 budgets, detection lower bounds or measurement qualification. `detailed_flow_count` counts actual distinct flow keys among selected examples, including flows shared by multiple patterns. To retain the existing publication byte ceiling despite additive metadata, new reports stably deduplicate identical `detailed_analysis` prose across examples (first occurrence order). Every distinct line and every per-example fact/measurement remains; this is not pooling, dropping examples or rewriting stored reports. Single-family selection/order is unchanged, but repeated summary prose in a newly generated multi-example group is no longer byte-identical to the predecessor.

The additive report-root DTO is closed and versioned:

```json
{"family_coverage":{"version":"network-family-coverage-v1","selection_policy":"family-first-v1","families":[{"pattern":"matched_resets","observed_groups":1,"retained_groups":1,"omitted_groups":0},{"pattern":"udp_duplicate_candidates","observed_groups":20,"retained_groups":19,"omitted_groups":1}]}}
```

`families` contains at most six rows, sorted by ascending ASCII pattern code, with no duplicate or unobserved family. The closed enum is `data_retransmissions`, `duplicate_acks`, `icmp_errors`, `matched_resets`, `syn_retransmissions`, `udp_duplicate_candidates`. Empty/no-pattern reports publish `families: []`. Counts are nonnegative safe integers, observed counts are positive, and each row has `observed_groups = retained_groups + omitted_groups`. Column totals equal summary `issue_count`, `displayed_issue_count`, `omitted_issue_count`; retained counts equal the actual issue patterns. These are counts of **observed issue groups**, not all network traffic or an assertion of complete detection.

The existing worker, stored job/public GET and report serializer carry this additive DTO without a new endpoint or storage migration. New `pattern-N` IDs are assigned **after** selection. Stored reports and existing AI references are not reselected, rewritten or renumbered on read; an identical ID in a new job is not a cross-snapshot identity.

Web treats absent metadata as legacy/unknown, never zero. Malformed-present metadata is atomically rejected with local feedback while valid observations and raw source data remain available; it cannot invent a clear conclusion. Metadata fields must be own enumerable data, with closed nested shapes, primitive enums and safe arithmetic. More than six rows are refused before row traversal, and inherited/accessor fields or coercion hooks are not evaluated. The validated absent/invalid/valid result participates in the existing evidence-change signature and same-job stale-citation latch. The bilingual compact notice distinguishes observed-but-unretained families; details mount lazily within the existing single coverage owner. Every retained group remains reachable in frequency order. There is no omitted-detail jump, additional fetch or nonexistent limit control.

AI input remains the first 20 selected groups. At the default report limit all retained families are supplied. At larger report limits final frequency ordering may put a minority family after input position 20; `omitted_input_issues` continues to disclose that omission. Family preservation is **not** promised for the AI projection at the 100-group report limit, and this change adds no v1 AI output fields or model invocation.

Regression fixtures: `test_network_family_selection.py`, `test_network_family_pipeline.py`, `network_family_fixture.py`, and `NetworkFamilyCoverage.test.tsx`. The legacy JSON fixture was captured from the actual accepted pre-change producer before editing it; it is not a new report with metadata deleted. New fixtures use checksum-valid packets, the real parser/FlowRecord, worker, SQLite reopen/public GET and actual Web default-App bridge. Maximum-limit cases are analyzer-only because the API retains its existing default. Synthetic AI controls establish citation lifecycle, not model quality, LIVE capability or independent acceptance.

## Production pattern report: bounded ICMP reporter details (ND-05)

New ICMP examples add a separate closed `icmp_details` object. Legacy `facts`, detection counts, grouping, family selection, source warnings, measurements and saved IDs remain unchanged. Example:

```json
{"icmp_details":{"version":"network-icmp-details-v1","samples":[{"reporter_ip":"192.0.2.1","protocol":"ICMP","type":3,"code":1,"quoted_flow":{"source_ip":"10.0.0.1","destination_ip":"203.0.113.1","source_port":50000,"destination_port":443,"protocol":"UDP"},"time":"2023-11-14T22:13:20.100000+00:00","packet_reference":null}],"omitted_event_details":0}}
```

The reporter is the **outer source**, not the quoted peer and not a proven failure cause. Outer `ICMP` and `ICMPV6` remain distinct. Quote endpoints preserve source→destination direction instead of canonical flow sorting; association is still sensor/interface scoped. A valid quote without an observed transport target retains the existing origin-flow fallback. Unavailable/truncated parser quotes are null; direct partial records preserve bounded known quote fields with null unknown leaves. Ports are null or uint16; quote protocol is null or TCP/UDP/ICMP/ICMPV6. IP literals are at most 45 characters. Type/code are uint8. Event time uses the existing UTC datetime precision (at most microseconds); this does not add exact-tick/M3 support.

**No available packet-reference branch is implemented.** Every sample publishes `packet_reference: null`. Productive parsing uses `retain_packet_bytes=False`, and FlowRecord carries no capture-bound ordinal. Even a retained parser's `raw_packet_index` is not dataset/capture-scoped authority and is ignored. Filtered/unsupported frames, record enumeration, timestamp matching and export fallbacks cannot create a reference. Original PCAP storage/export remains unchanged.

Retention applies simultaneously to pending quotes and final observations: first four admitted event details per final observation, at most 2,048 samples globally and 262,144 canonical UTF-8 payload bytes. Every scalar is bounded before copying/serialization. No reporter set or discarded history is kept. An internal admission ordinal restores capture traversal order across pending owners; it is never exposed as packet index and is not timestamp ordering. Merging transfers ownership, returns credits for discarded samples exactly once and clears old owners. Observation-limit discard also returns credits while preserving its existing detection lower-bound warning. Previously omitted samples are not backfilled after end-of-scan credit return.

Retained-payload accounting charges each sample's canonical JSON plus one separator byte. Fixed counters and bounded owner/list overhead are separate from payload bytes; they do not grow with omitted history. The byte cap can bind before 2,048 samples (the serialized minimum sample is larger than 128 bytes); tests do not raise the production byte cap to fabricate an exactly-2,048-sample state. Reduced sample limits independently exercise slot admission/return.

Publication visits only selected examples (default 20×3; analyzer maxima 100×10). It reserves the entire canonical array of `{"icmp_details":...}` envelopes with empty samples, including keys, omission integers, braces/brackets and separators, then adds deterministic sample prefixes using exact bounded contributions. It never reserializes the whole report once per dropped record. An injected byte limit too small for all selected zero-sample qualifiers raises a concrete policy error rather than hiding omissions or exceeding the limit. `omitted_event_details = example.event_count - len(samples)` includes retention and publication omissions, not detections, groups or representative examples. Detail-only caps do not alter coverage, tracking credits or event counts.

Canonical encoding is Python `json.dumps(sort_keys=True, separators=(",", ":"), ensure_ascii=True, allow_nan=False)` encoded as UTF-8. Accepted IP/protocol/time strings are ASCII; escaped/arbitrary strings are rejected. Python validates the produced closed nested shape before publication. This does **not** change the backend's literal stored-report read policy. The Web validates original own enumerable data properties before projection, strict primitives and dense arrays bounded before traversal, exact omission arithmetic and aggregate publication bounds. Absent legacy details mean unknown; malformed-present details fail atomically locally without removing positive evidence or raw facts. The actual validated absent/invalid/valid semantics participate in the evidence signature and existing stale-citation latch.

The decoded DTO numeric policy is **integer-value**, not integer-token spelling: ordinary builtin Python `int`/`float` values and Web numbers must be finite, integral and nonnegative, with unchanged uint8 type/code, uint16 quoted-port and safe-integer event/omission count bounds (maximum 9,007,199,254,740,991). Thus `1.0`, `0.0`, `-0.0` and valid integral exponent spellings are accepted after standard JSON decoding. Booleans, strings, required nulls, fractional decoded values, nonfinite values, negatives, out-of-range/unsafe values and custom numeric subclasses/objects are rejected without coercion or callbacks; nullable quote ports remain nullable. This is not lossless lexical-number validation: decoder rounding/underflow beyond its precision cannot be reconstructed. Producer TypedDicts and canonical output still use integers. `sample()` and `_port()` retain strict integer **source admission**, and stored reports are not rewritten. Numeric-value parity does not equate raw wire spelling lengths: aggregate canonical metadata accounting and its 262,144-byte production cap are unchanged.

The bilingual UI lazily exposes one representative/event detail at a time. Every retained sample is reachable without another fetch, including examples beyond the three legacy raw-fact cards. Reporter, directional quoted flow, unknown reference and event-detail omission units are distinct; the instructions describe passive evidence review, not active network diagnosis. No packet jump/download/filter is invented. Existing coverage/evidence ownership and keyboard controls remain. The AI projection still uses its unchanged numeric whitelist, first 20 issues and 24,000-byte budget; addresses, quoted endpoints, payloads and this new metadata are not supplied to the model.

Regression witnesses are `test_network_icmp_details.py`, `test_network_icmp_details_pipeline.py`, `network_icmp_fixture.py` and `NetworkICMPDetails.test.tsx`. The legacy JSON was captured from the actual accepted ND-04 producer before editing it. Public-path cases exercise checksum-valid IPv4/IPv6 PCAP → parser → FlowRecord → actual worker → SQLite consumption/reopen → ASGI GET → existing Web and actual AI input projection, without invoking a model. Maximum 100×10 cases are model-validated parser-derived analyzer inputs, not an API-default claim. Synthetic AI outputs only test citation ownership and DOM bounds, not model quality or deployed/NIC acceptance.

## Network AI: typed numeric source evidence (NA-AI-001)

New manual network runs use `network-ai-input-v2`, `network-interpretation-v2` and prompt version `2.0`. The original v1 builder/validator remains for compatibility; recognized terminal v1 runs display legacy prose without verified numeric evidence. Unsupported queued snapshots fail with `NETWORK_INPUT_CONTRACT_UNSUPPORTED` before provider I/O and are acknowledged by the existing worker. They are never silently upgraded. C2/DDoS transport retries and cancellation ownership are unchanged.

The 24,000-byte minimum-first projection retains first-20 issue identities/counts/times before optional units. Optional facts and measurements carry original `example_index` selectors, not compacted array positions. Source integer observations are bounded canonical decimal strings; timing statistics remain finite JSON numbers. Counts, measurement-source conservation, quality and bounded optional-unit accounting are validated, including measurements which do not fit the projection. V2 strings use Unicode scalar limits and reject unpaired surrogates; no normalization is performed.

The provider supplies required reference lists (at most three per section item, 24 total), never values, units, confidence or computed metrics. Closed variants select summary/issue counts, original-example facts or metric/direction/statistic combinations actually retained in the input. Duplicate references, foreign item ownership, omitted/null measurements and singleton dispersion are rejected. A genuine observed zero count remains valid. `INVALID_NUMERIC_REFERENCE` diagnostics contain no rejected text.

The server resolves a separate `network_numeric_evidence` envelope from the stored input/output on every ordinary run-publication path. Values are canonical numeric strings and units/coverage/sample/quality qualifiers come solely from the source registry. The complete envelope, including immutable run/job/dataset identifiers, must fit 32,768 bytes inside the existing output-validation/one-repair cycle and again before completion/publication. The identity-only floor is checked before provider I/O. A stored cache is ignored. Corrupted completed v2 data fails the entire requested response with HTTP 503 `NETWORK_EVIDENCE_INVALID`, message `Saved network evidence could not be validated.`, and no diagnostic details. Nonterminal, failed, cancelled and v1 runs omit the field; completed valid zero-reference runs include an empty items array.

Web re-resolves received references, values, units and qualifiers rather than trusting a self-claimed hash. Integer comparisons use decimal strings/BigInt; they never round through binary64. Verified presentation additionally requires matching selected run/job/dataset and current report source values. Unsafe current-report integers or filtered/malformed example arrays cannot establish provenance, so all verified rows and navigation are suppressed together. This is deliberately not a lossless current-report wire upgrade or a fully verified 63-bit report-parity claim. Same-run input/output changes and observed same-job report changes are latched; identical rereads retain usability.

The bilingual facts region is separate from unverified AI prose: an AI sentence claiming 1100 ms does not alter a referenced 100 ms observation or become verified through that reference. It preserves representative-flow scope, RTT sources/exclusions and sample limitations, and separately labels producer, whole-input and optional-unit omissions. Opening facts, keyboard source navigation and changing labels do not initiate inference. Source navigation closes the full AI detail owner. Tests retain the original v1 controls and add actual parser → gateway scripted transport → worker → SQLite reopen → public API → Web fixtures. Scripted provider and loopback built-browser checks are not real-model, deployment or physical-capture acceptance.
