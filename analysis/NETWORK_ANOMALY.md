# Network anomaly POC contract

This document describes the retained legacy API. The production pattern report uses `c2hunter_analysis.network_report.analyze_network_report`.

Legacy entry point: `from c2hunter_analysis.network_anomaly import analyze_network_anomalies`.
Call `analyze_network_anomalies(records, *, max_packets=100000, max_flows=1000)` with `parse_pcap(..., retain_network_evidence=True, retain_packet_bytes=False).records` **before flow aggregation**. Evidence retention defaults to false, preserving existing `Flow(**record)` callers. No C2 scoring/model/schema replacement. Records lacking packet evidence are accepted as incomplete; no guesses from aggregate flags.

Returns a plain JSON-safe dict with `version: "network-anomaly-v1"`, `summary`, `flows`, `warnings`, and `limitations`. Each flow has `sensor_id`, `interface_id`, `protocol`, `endpoint_a`/`endpoint_b` (`ip`, `port`), `observed_directions` (`a_to_b`/`b_to_a`, each packets/bytes), `metrics`, `warnings`. Metrics: `syn_retransmissions`, `data_retransmissions`, `duplicate_acks`, `matched_resets`, `udp_duplicate_candidates`, `icmp_errors`, `icmp_error_details`, `observed_rtt_ms` (count/min/max/mean), `interarrival_variation_ms` (directional count/min/max/mean/stddev), `ttl_observed` (directional min/max). Counters count observed repeats, not proven network loss. Missing measurement summaries have count 0 and null extrema/mean.

`metrics.icmp_error_details` is an array of at most 16 objects:

```json
{"type":3,"code":1,"reporter_ip":"203.0.113.1","quoted_flow":{"source_ip":"10.0.0.1","destination_ip":"203.0.113.1","source_port":50000,"destination_port":443,"protocol":"UDP"}}
```

`quoted_flow` is null when unavailable. Errors appear on the ICMP flow and, when the quoted TCP/UDP tuple exists in the same sensor/interface, on that transport flow. Do not sum these counters as unique capture-wide errors. Quoted association does not add reverse-direction transport packets.

Endpoint ordering is deterministic, not an inferred client/server. Missing or null `capture_interface_id` is retained as the explicit unknown group (`interface_id: null`), separate from every known interface including 0. Unknown records with the same sensor/protocol/endpoints share that group; it does not establish a shared capture vantage. Historical/aggregate records retain directional packet/byte totals and carry `INCOMPLETE_PACKET_EVIDENCE`; packet measurements cannot be inferred from aggregate flags. Scope is per sensor AND capture interface: never correlate unsynchronized vantages. A missing direction (`ONE_DIRECTION_OBSERVED`) is unknown capture visibility, NOT evidence of bad routing. No route bypass or asymmetric-route verdict is emitted. TTL and ICMP are supporting observations only, not proof of path identity. Interarrival variation is NOT one-way jitter. Duplicate ACK needs repeated seq/ACK/nonzero window, no payload or SYN/FIN/RST/URG, and outstanding reverse-direction data. TCP sequence, ACK, window, payload length and complete packet evidence are required. RTT excludes retransmitted/ambiguous ranges (Karn), including SYN retries, and measures capture-point request/response time (including delayed ACK), not host end-to-end latency. UDP duplicates are directional payload-hash/length candidates, never transport retransmission. All counts remain lower bounds under capture gaps/limits; duplicate capture itself may mimic retransmissions.

Parser additions are opt-in packet-record evidence only. Existing aggregate Flow and PacketObservation are deliberately unchanged. Default scan limit is 100000 records (caller may choose 1..2000000), output limit 1000 flows (caller may lower), and correlation identities are capped at 256 per flow. `PACKET_LIMIT_REACHED`/`FLOW_LIMIT_REACHED` set summary truncation; `FLOW_STATE_LIMIT_REACHED` disables further correlation for that flow. ICMP detail output is capped at 16 per flow. A gap over 60 seconds clears correlation state; a new TCP SYN or RST resets the connection epoch. FIN closes one sending direction; TCP state is retired after both directions' FINs have been acknowledged, preserving outstanding evidence during half-close. Non-monotonic timestamps disable subsequent correlations for that flow. Truncation/incomplete warnings and limitations must be shown by consumers. This is bounded capture-local observation, not a loss/latency diagnosis.

TCP ACK correlation uses bounded extended sequence coordinates across the 32-bit wrap boundary. Stale, beyond-observed-frontier or half-space-ambiguous ACKs cannot retire data or establish duplicate-ACK evidence. Existing conservative RTT ambiguity exclusions remain; this is not a full TCP reassembly stack.

For SLL2 packet evidence, the parser preserves observation-point isolation using a capture-local opaque uint32 identifier for each `(global container interface ordinal, SLL2 ifindex)` pair. This identifier is not the original OS interface index. Mapping is deterministic in capture order, collision-free with container interface ordinals, and capped at 65,536 entries. An unknown zero ifindex or exhausted mapping yields incomplete packet evidence rather than cross-interface correlation. Non-SLL2 IDs and raw export container-interface IDs, packet ordinals and bytes are unchanged. Separate captures still require distinct caller-owned source namespaces.
